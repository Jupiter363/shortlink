# Outbox确认与元数据吞吐优化

日期：2026-09-07；分支：`codex/production-refactor-v07`。状态：实现、单元/集成验证、有界复测、最终对账及环境收尾完成；100/s创建未通过，生产容量未签收。

## 已确认的瓶颈

基线为[上一轮复测](08-首轮压测问题优化与复测.md)运行 `20260906T184635Z-01cf29e7`。创建100/s在29.822秒暖机内触发Outbox2107条积压保护；约25秒观察区间输入198.49事件/s、PUBLISHED128.32事件/s，积压增长70.16事件/s。Kafka发送队列为0，ACK任务队列持续约50条。瓶颈可定位到收到Kafka回调后的ACK执行/数据库记账段，尚不能把提交、SQL执行、锁等待各自成本分开，更不能归因为Kafka Broker或统计消费。

metadata接收另有逐条提交成本：一次poll最多16条，但每条accept各开一次事务。50/s停止输入时，路由20332条、metadata任务19144条，1188个意图尚未进入任务表，约25秒才追平。表内pending低不代表整条链路没有积压。

worker调度也有限制：原来每次定时唤醒最多补4个任务，空闲线程必须等下一个tick。默认poll1000ms、压测poll50ms会形成不同的调度上限；不能用压测配置结论替代生产配置。

## 本轮实现与验收范围

1. Outbox保持总在途64、4个发送线程和4个ACK线程，新增每批最多16条、最多等待2ms的ACK事务，保留eventId/fence/SENDING条件与租约恢复。Kafka回调仍只入有界队列。事务成功后才统计已发布结果，未知提交不补算成功。
2. metadata同一有界poll中的有效任务与毒消息DLQ持久化合并为一个独立事务，数据库提交完成后才提交Kafka offset；数据库或offset不确定时从已提交offset重放，任务和DLQ保持幂等。4个worker采用有限任务数/任务边界时间预算继续领取，空队列、失败和关闭停止补位。
3. 补充claim、ACK事务和metadata intake观测。当前纯创建夹具的未入表差额为routeCount减metadata.total，未完成metadata为差额加表内pending；它包含尚未从Outbox发布的意图，不能直接叫Kafka lag，也不能再与Outbox相加。新门禁分别限制两者，缺失数据不补0。
4. 完成相关单元、真实数据库/Kafka集成测试后，以相同资源、保护参数和`.local`受控拒绝模式重测25/50/100创建、两种目标50行/s批量，以及创建/跳转冒烟和代表性网关档位。全部通过且队列排空后，追加一次100/s、5分钟测量观察积压增长；不构成三轮稳态或生产容量签收。

Agent、Flink/ClickHouse统计消费、真实网页抓取、TLS和多实例故障演练不在本轮；历史失败与原始数据保留。

metadata intake返回的accepted/rejected是已确认提交的输入记录，含重放；不与数据库唯一任务数直接作等式。worker量子的1秒只在任务边界检查，单次在途抓取可能更久。正常抓取失败成功持久化后可以继续其它任务，数据库完成提交未知不改判为抓取失败。关闭前已进入的claim可能提交，随后不再启动新抓取，保留既有租约恢复。

## 关于Kafka扩容

Kafka支持增加Broker并将现有分区迁移到新节点；新Broker不会自动接管已有分区。[官方扩容说明](https://kafka.apache.org/43/operations/basic-kafka-operations/)。这属于部署容量调整，不能直接消除应用逐条ACK数据库记账的成本。本轮保持Broker、分区、副本及资源原值，先验证代码优化；没有据上轮积压断言Broker容量已打满。

## 下一步优化边界

代码复核确认metadata每任务仍有领取和终态写入两个事务；当前有效目标终态路径连同候选查询至少约17次应用SQL调用，另有组锁内部成本。`MetadataJobService.lockFence/assertFence/finish`存在重复围栏、数据库时间读取，`MetadataRuntime`每次补位查询多个候选后只接续一个任务。观察支持优化这些往返，但没有EXPLAIN或逐SQL耗时，不能断言全表扫描或某一行锁就是主因。

下一轮先增加candidates/claim/apply分段计时，合并已持锁事务内可消除的重复读取，最终写回保留owner/fence/state/实时租约及影响行数核验。必须回归旧租约、租约到期、移组、目标版本变化、提交未知等场景，再以相同4个worker比较。之后才单独做worker扩展实验，检查吞吐、数据库锁等待、连接池和外部抓取并发；生产默认1000ms空闲轮询也需独立验证。本轮未实施这些后续修改或扩容。
