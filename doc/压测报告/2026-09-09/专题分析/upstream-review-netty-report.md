The shared accept path provides a mechanism for delayed user-space acceptance when its event loop is busy. TCP connect completion is not identical to user-space accept completion; connect-timeout attribution also depends on the kernel handshake/listen queues and client-side event processing. A shared listener by itself does not explain why all 119 connect timeouts were assigned to one APISIX worker. Different per-worker connection creation/reuse exposure is a possible distinction for the parent APISIX review, not a finding proved here. Parent-reported no ListenDrops does not support claiming proven listen-queue overflow. No timeout, backlog, queue or product change is proposed by this review.
