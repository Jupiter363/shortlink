## 当前限流配置及算法

配置源为 `deploy/apisix/apisix.yaml`，Java 源为 `gateway/.../filter/GatewayAdmissionFilter.java`。

| 层级 | 算法或机制 | 当前原值 | 作用范围 |
| --- | --- | --- | --- |
| APISIX 管理路由 | `limit-req` 漏桶 | rate=100/s，burst=100 | 每节点、每路由、每来源 IP |
| APISIX 跳转路由 | `limit-req` 漏桶 | rate=1000/s，burst=200 | 每节点、每路由、每来源 IP |
| APISIX 两类路由 | `limit-conn` 活跃请求并发计数 | conn=200，burst=100 | 每节点、每路由、每来源 IP |
| Java Gateway | `Semaphore.tryAcquire()`，零等待队列 | 每实例最多 64 个在途请求 | 会话读取、请求体读取及上游请求共享预算 |

漏桶根据经过时间按 rate 消减超额计数，并根据 burst 决定拒绝或延迟；已读取实际 APISIX 镜像内的 `resty/limit/req.lua` 核实。当前 `key=remote_addr`、默认本地策略，不是全局分布式配额。若正式环境前置负载均衡，还需按实际可信代理拓扑配置真实来源地址，否则 `remote_addr` 可能代表前置代理。上述原值仍需后续容量测试和实际流量分布校准，不能等同于集群 QPS 上限。
