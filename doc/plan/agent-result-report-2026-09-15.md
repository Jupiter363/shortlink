# 双 Agent 分析报告布局

关联 Issue #57。用户进一步明确，主要需要设计分析后的页面；初始分析方向卡片保留，删除与左侧导航重复的“数据核验”模块。

## 问题分析

返回回答后，左侧完整提问卡继续占据约三分之一宽度；右侧标签、状态、操作按钮及回答标题重复分行，阅读正文前有较多间隔。正文按纯文本展示，Markdown 的粗体、编号、代码标记直接外露。证据与执行记录被整页切换隐藏，提示在末尾容易漏读。接口完整返回并不代表统计查询已执行，缺少分组时尤其需要区分。

## 设计

- 结果态使用完整报告区域，提问设置通过“继续分析”弹窗打开。运行中提供停止前端等待，失败时可调整问题；原有独立会话和迟到响应保护保持。
- 报告标题、复制、导出、继续分析集中在同一行。下方明确本次提交问题、提交范围及前端接收回答的时间。
- 主阅读区前置返回的提示与数据缺口，正文以安全 Markdown 显示，控制行长、段距及层级。
- 右侧显示真实证据目录、来源说明和工具执行概况；详细证据、动作、来源与轨迹通过抽屉查看，不挤压正文。
- 投放报告强调分析解读，风控报告强调研判意见及执行核验；不从正文推断风险等级，不构造统计图表或缺失指标。
- 手机以正文为先、侧栏自然下排。表格可横向阅读，长文本折行；仅正文或打开的弹窗拥有主滚动。

## 数据边界

证据数量包含工具警告卡，来源数量也可能包含 Graph、模型与工具说明，均不代表成功查询数量。工具状态使用已有归一化 outcome/tone，未知保留未知。动作数组可能包含已执行命令；“命令已提交”和“传播已生效”保持区分。历史保留提交时范围，失败后的旧回答明确标注。

Markdown 采用 Vue 文本节点和固定标签渲染，不使用原始 HTML；链接、图片和未支持语法保留为文字，不加载外部资源。预览样例在独立本地 harness 中运行，不进入正式构建，不触发业务调用。
