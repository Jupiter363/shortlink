# 风险中心仪表盘设计

关联 Issue #52。对象是短链管理者日常查看风险画像、证据与策略执行的后台页面。

## 现状问题

1. 概览只有两张大卡片，桌面下半部大面积留白；六个指标嵌套在一张卡片中，主次不清。
2. 档案、事件、策略回执通过整页切换隐藏，无法同时判断当前风险与近期事件。
3. 趋势缺少刻度，0 分被抬成 2% 柱高；实际画像日期与缺失状态不够清晰。
4. 内联展开说明挤占卡片；原始原因码在日常预览中难以快速阅读。
5. 现有事件接口默认只查询 SHORT_LINK；失败后仍显示“共 0 条”，会把错误误读为空结果。

## 设计方向

继续使用现有木星主题与 Vue/R 组件，不增加另一套组件库。沿用 taste-skill 的先审视再改造、统一文字层级、留白与形状原则；该 skill 不覆盖后台仪表盘，营销页视觉规则不套用到风险数据。按风险研判的业务顺序组织专属工作台，与访问统计的指标卡和维度图表区分。布局变化 5、动效 2、信息密度 6。真实缺失值保留“—”。

- 顶部导航仅保留页面标题；正文轻量工具条放分组、刷新与数据说明。
- 首屏为一体式态势面板。左侧约 250px 的判断区按等级使用浅绿、浅黄、浅红或未知浅灰，搭配深色文字、大号评分和 0 / 40 / 70 / 100 评分刻度；右侧白色区域呈现近 7 天轨迹，底部连续分级条列出高、中、低风险短链数量。图形模式约 300px 高，表格模式自然展开。
- 第二层为三列研判区：短链核查、事件时间线、约 224px 的操作区。工作区最大宽度 1440px，核查与时间线维持紧凑比例；卡片按内容增高，取消列表内部滚动框。历史事件与当前画像在空间和文字上均分开。
- 深入研判、人工审核、执行核验三个入口上移到研判区右侧纵向排列；1100px 以下上移为双栏前的横排操作区，760px 以下回到单列阅读顺序。人工关注仅表示审核状态，策略命令仅计本次登录保留的数据。
- 隐藏仪表盘正文滚动条，但保留单一正文容器的滚轮、触控及键盘滚动；列表与趋势表格不再形成嵌套滚动区域。完整档案仍通过抽屉查看，手机使用档案卡片；趋势保留图/表切换和键盘交互。

## 数据与操作

总览直接使用服务端画像字段；头部档案最多 10 条、全部档案最多 500 条，不能回算全组数量或均分。分级数量不替换成待处置数，未知数量不补为低风险。评分刻度依据后端 RiskLevel 的 40 / 70 分边界；低风险不等于安全。

趋势使用真实日期间距，零分柱高为零；缺失、重复或空分数不连线，非法日期保留在表格中。图和表均可键盘读取。

事件预览保留第一页最近记录，打开全部事件后的分页不替换首页预览。事件失败显示错误而非零总数，分组切换清除旧预览。标题说明明确短链事件范围。档案加载中或失败时也不显示“0 / 0 条已返回”。

统计口径放标题后的问号，悬停/聚焦查看。完整档案增加本地搜索与风险等级筛选，已知原因码显示中文说明，详情证据保留原始信息。

人工审核、当前策略与命令传播三类事实保持独立。现有有效 linkId、策略激活/撤销状态、操作锁、原命令 ID 复核和相同 revision 分页保护保持。布局验收仅执行只读与打开/取消操作，不提交审核或停用策略。
