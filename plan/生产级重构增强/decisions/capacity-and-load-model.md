# 容量假设与负载模型（未执行压测）

用户明确优先完成稳固实现，QPS 后测。集群峰值 100000 次跳转/秒只是规划输入，当前没有机器预算，也没有单机或集群吞吐承诺。

首轮具体执行顺序、接口、档位、采样和停止规则见 [接口与网关跳转压测计划](../06-接口与网关跳转压测计划.md)。该轮先接口、后 APISIX 跳转；以下完整负载组合保留为后续 M6 范围，不等同于已执行或全部纳入首轮。

容量计算至少分别记录：成功 GET、HEAD、业务拒绝、未知短码、边缘拒绝、创建/更新、批量导入与后台查询。两条 raw 流各自计量，不能把事件数假定为跳转数。示例：每秒十万条、每条 1 KiB 的单事件流，未压缩约 8.85 TB/天；7 天和三副本约 186 TB，尚未包含索引、派生、归档和其他流。存储及保留期必须按实际事件大小、压缩率与业务日曲线重算。

待单独授权执行的负载组合：

1. 小工作集热链、Zipf 热点与长尾混合；记录 L1/L2 命中、单链热点和源数据库实际回源量。
2. 随机未知短码、缓存失效广播丢失、Redis 不可用；验证硬限额内拒绝，不能让请求堆进 DB 或无界队列。
3. Kafka 单流积压/不可用、生产端队列字节耗尽；跳转时延、事件质量和点击/拒绝口径分别观测。
4. 单条与 500 行创建、501～50000 行任务、不可变文件导入；测业务锁、ID 预取、Outbox 延迟、额度与取消接管。
5. 同时在线统计、历史补算与长查询导出；测 Flink checkpoint 时间、CH 扫描/内存、控制库压力，确认隔离预算。
6. 多副本 CH 落后、恢复、Kafka 重平衡及 Worker 旧租约晚提交；功能断言继续成立后才统计吞吐。

每次输出版本/配置摘要、机器 CPU/内存/磁盘/网卡、预热/稳定测量/恢复区间、 offered/completed QPS、HTTP 分布、P50/P95/P99、CPU/GC、连接池、队列、lag/覆盖及错误原因。未到达稳态或通过拒绝大量请求得到的低时延，不能作为目标容量通过。

运行地址必须是显式新建的隔离数据集和测试环境；不使用原开发库，也不默认向生产施加负载。本文件是后续测量输入，不是压测报告。
