# 验收矩阵与首次上线准备

> 状态：v0.7 实施规范；代码、实际测试与保留边界见 [实施验收记录](04-实施验收记录.md)。压力测试和完整 E2E 按用户要求另行执行。
> 适用场景：项目仍在开发，全部目标能力开发完成后首次上线。
> 本文保留完整验收目标，不将未执行的压力/E2E场景标记为通过；尚未部署正式环境。

导航：[架构总计划](shortlink-production-refactor-v2-apisix-kafka-flink-clickhouse.md) · [开发阶段与任务拆分](01-开发阶段与任务拆分.md) · [Agent 与异步统计链路重构](03-Agent与异步统计链路重构.md)

## 1. 验收边界

- 保留完整目标栈：APISIX、Java 服务、Kafka、Flink、ClickHouse、MySQL、Redis、Nacos。
- 首次上线即采用 APISIX 直达 Redirect；内部 Java Gateway 只承接管理 API 的 Redis Session 鉴权。
- 不设置 G0～G3 旧生产切流，不要求连续七天线上影子流量，不在线回填旧统计。
- 首版从全新 schema 和明确初值启动；有价值的开发数据仅可按离线导入方案选择性保留。
- 全新 schema 不等于允许删除现有库；任何初始化脚本都不得自动清空已有数据或未知数据库。
- 网关加固、Kafka 消息队列解耦及完整分析链路、号段与批量生成三条主线都必须完成，不以 QPS 或硬件预算决定是否实施。
- 发号器默认采用固定 SHA 的 Leaf Segment 必要源码内嵌适配到 id-generator，不直接依赖官方二进制包或部署 Leaf RPC；替换旧 UUID/Hash/Bloom 碰撞重试，动态 Step 在 M3 交付且可关闭。
- Agent Tool 与现有定时风险画像复用 Admin 授权→Analytics 统计链路；Agent 不额外消费 raw 事件、不自建计数存储，首版不新增 Agent Kafka consumer/Inbox。
- 验收面向最终行为及故障不变量；旧实现与旧统计结果不自动成为正确性基准。
- 本文的“通过”均要求证据；勾选清单、服务启动成功、单机演示不等于生产验收完成。

## 3. M0 契约与逐阶段参数

以集群 10 万跳转 QPS 作为已确认的容量规划假设，用于暴露瓶颈、比较拓扑与估算预算。
实现稳固优先，QPS 是最后的测量结果：正确性、资源有界和故障恢复不可妥协，10 万不作为脱离硬件的硬性通过条件。
M0 冻结正确性语义、候选开发参数、测试方法和数据生成规则；硬件预算落实、容量测试结果均不阻塞三条主线开发。
延迟/错误预算、测量时长与运行资源在实现过程中完善，并在 M6 对应测量前固定；实际可靠容量由 M6 最终实测得出。

| 参数组 | 必须记录的值或决定 | 验收用途 |
|---|---|---|
| 负载模型 | M0 定义活跃短链数、热点 80%/单超热 key 分布、跳转/创建比例等生成方法；具体规模在 M6 运行前记录 | 保证测试可复现，不要求先具备生产规模机器 |
| 服务目标 | M0 定义 APISIX 入口到响应的 p99、管理 API 延迟分位、错误率及统计可见延迟的测量方法 | 候选预算随实现验证，M6 测量前固定，按一致预算确定可靠容量 |
| 故障目标 | 允许恢复时间、允许数据损失范围、缓存/策略最大陈旧时间、Outbox 积压预算 | 明确恢复与降级是否合格 |
| 事件语义 | 何时算点击、eventId 生成及重用、投递确认边界、队列满和进程崩溃行为；独立结果事件的生产阶段/拒绝原因/身份与去重 | 区分响应成功、已排队、持久接收和可查询；不以点击流推算被拒绝请求 |
| 统计口径 | PV、UV、UIP、业务时区、自然日边界、HEAD/拒绝计数、迟到与修正规则 | 生成独立预期结果，避免以旧统计作真值 |
| 去重与重放 | 在线去重期限、重放标识、重放输出版本、隔离表/Topic、结果替换方法 | 避免历史重放再次累加在线结果 |
| 身份与域名 | 用户/租户主体、gid 归属、域名注册、Host/IP 规范、Cookie 属性与生命周期 | 各入口和服务采用一致语义 |

| Agent 证据 | M0-05 定义 StatsEnvelope、三窗口共同 effectiveEnd/snapshotId、缺失状态、long 计数、本地读取 scope 及自动动作 expectedPolicyRevision/executeBefore | 本地画像读取也先授权；证据检查不能代替 Command 新命令事务内最终复核 |
| 路由状态 | routeVersion、删除墓碑、失效时限、回源与回填竞态的仲裁规则 | 防止旧值回填、缓存清空后复活 |
| ID 与导入地址 | Leaf 来源 SHA/适配清单、全局 biz_tag、排他区间、置换版本、唯一约束、高水位、动态 Step 与专用池预算 | 发号器与离线导入共享唯一性边界；首版不开放用户自定义短码，Leaf 不新增 RPC 服务 |
| 批量状态 | VALIDATING/READY、验证资源预算、实际可执行行数、幂等/准入事务、分块提交、事务内 fencing、额度结算及输入对象 version/checksum/parser | 验证 Job 可先持久化；链接额度在真实可执行行数确定后的 READY 准入预留，重试不换输入或重复扣额 |
| 统计发布 | raw archive sourceCut、cluster/topic 身份、LogAppendTime 接收时间与 validationVersion/结论、归档对象、构建/覆盖、recoveryEpoch、manifest CAS/fencing 及副本资格 | 固定原始判断上下文；独立控制库恢复不沿用旧世代或跳过缺失覆盖，消费者确认不冒充查询完整 |
| 账号与初始化 | 本人字段白名单、密码散列参数、Session 最小字段/认证版本、改密与并发签发撤销、注册幂等身份及默认组初始化状态 | 不允许请求体指定他人主体；跨服务初始化可恢复且只形成一个默认组，不假设跨库事务 |

| 版本与容量 | M0 登记 JDK、Spring、Kafka/Flink/CH、连接器、APISIX、etcd/Nacos 兼容组合；M6 记录实际硬件、拓扑与压测客户端 | 让结果可复现；实现不等待机器采购或先测得目标 QPS |

可调开发样例：1,000 条合成短链、20 个并发客户端、单任务 1,000 行、2 个 Redirect 实例。
这些样例用于缩短反馈时间；M6 按实际可用部署记录负载和拓扑，再报告该组合的容量与适用限制。
出现业务拒绝时分别统计 401/403/404/429 与基础设施错误，不用单一“失败率”掩盖差异。

## 4. 证据格式

每个场景至少记录：测试 ID、执行时间、代码提交、schema/契约版本、镜像摘要、配置摘要、输入及断言结果。
涉及并发或故障时，补充随机种子、实例数、故障注入位置、关键时间线、恢复步骤与状态查询。
涉及性能时，补充机器规格、数据量、预热与测量区间、客户端分布、原始采样和服务端资源指标。
截图可辅助说明；数据库断言、请求记录、事件样本、指标导出及可重跑脚本是主要证据。
证据中的 token、Cookie、原始 IP 和敏感 URL 参数应脱敏，保留可关联的测试标识。
矩阵中的证据名称是待交付材料类型，不表示这些文件已经存在或测试已经通过。
本版共 135 个唯一场景编号：C01～C03、A01～A12、T01～T04、R01～R11、P01～P09、K01～K05、I01～I16、B01～B11、S01～S23、E01～E12、AG01～AG20、L01～L09；更新既有场景不重复计数。

## 8. M4 统计、迟到与重放

M4-04 的生产交付为 `analytics-worker/` 及独立统计控制库 DDL `deploy/mysql/002-analytics-control-schema.sql`（均 planned）；其归档、sourceCut/覆盖记录、补算与 manifest 发布入口须随正式制品部署。验收脚本只驱动并核验生产入口，不能代替长期运行能力。规范补算从冻结 raw archive cut 先筛选原始接收记录，再按 eventId 去重，不把可被覆盖的 CH 规范行当历史来源成员关系的唯一证据。

raw Topic 显式设置 `message.timestamp.type=LogAppendTime`，消费者校验 `timestampType` 并将 `timestamp()` 作为受控 broker 的接收/追加时基保存；`occurredAt` 仍是事件体中的业务事件时间。接收身份同时保存 cluster/topic 身份、partition/offset，归档及重算沿用原始 `receivedAt`、`timestampType`、`validationVersion` 与校验结论，不用重放时的 now 或新 Topic 的追加时间。broker 时钟误差预算和异常处置随契约验收。设置及覆盖语义见 [Kafka Topic 配置](https://kafka.apache.org/40/generated/topic_config.html)、[ProducerRecord](https://kafka.apache.org/41/javadoc/org/apache/kafka/clients/producer/ProducerRecord.html)；消费者字段见 [ConsumerRecord](https://kafka.apache.org/41/javadoc/org/apache/kafka/clients/consumer/ConsumerRecord.html)。这些资料用于核对协议，实现仍绑定 M0 冻结的实际版本。

### 9.1 Agent 复用统计链路专项

本节使用 AG01～AG20，与身份授权用例 A01～A12 分开编号；关联任务见 01，契约详见 03。M5-08 接通现有风险中心查询与人工操作，继续复用 Analytics 和 Command，不新增 Agent Kafka consumer。

### 10.1 容量报告的执行口径

1. 固定服务器 CPU/内存/磁盘/网络、实例数、Kafka 分区、Flink 并行度及压测客户端规格。
2. 固定数据规模、命中率、热点分布、请求体大小、TLS/连接复用方式和风控策略组合。
3. 从 APISIX 入口采样到客户端收到 302，记录端到端 p50/p95/p99、错误分布和实际吞吐。
4. 启用真实策略判断、Cookie、Kafka 事件发送与对应持久化边界，同时记录事件丢弃/积压及统计时效。
5. 先验证客户端自身有余量；阶梯提高负载，每阶保持本轮开始前冻结的测量时长并验证不变量。
6. 达到延迟/错误预算、队列持续增长或保护上限时记录容量边界；过载测试结束后验证能恢复。
7. 对普通分布、热点集合、单超热 key、批量混合及 N-1 分别给出结果和容量边界。
8. 给出可靠容量、首要瓶颈、10 万规划假设的资源差距及下一步优化依据，允许实测值低于规划值。

首次上线准入上限必须低于该部署组合的实测可靠容量，并低于需要保障的 N-1 场景容量，额外预留 M6 运行方案规定的余量。
该上限须落实到已验证的入口/服务总并发和配额设置；APISIX 实例级限流不能冒充集群总上限。
硬件、拓扑、关键策略、流量分布或持久化语义改变后，需要重测受影响容量；开发样例不能直接换算为生产承诺。

## 12. 失败处置与完成定义

权限越界、SSRF 可访问受限目的地、ID 重用、策略/删除复活、任务重复提交以及无法解释的统计重复属于阻断项。
Agent 丢弃质量元数据、未知补零、窗口/分页混快照、计数溢出、旧证据覆盖画像，以及绕过确定性门槛或重复执行风险动作同样属于阻断项。
空交集被当成无约束、自然时间边界不推进、删组并发留下孤儿、孤立额度预留、旧 Worker 越代提交、导入输入混版、CH 落后副本伪报 COMPLETE、固定 cut 重建漂移，以及归档/补算仅能由临时脚本运行，均须阻止相应能力上线。
风险中心用历史建议/本地审核冒充当前策略事实、误报/关注隐式撤销，以及画像刷新覆盖人工标注，也按阻断项处理。
本地画像先读后鉴权、账号越权修改/密码泄露、旧 authVersion 会话继续授权、注册重复默认组、自动新命令绕过事务内前置条件、恢复控制库后跨世代发布/跳过来源覆盖、同 cut 时间校验漂移、验证未完成即预留链接额度或执行、旧元数据回写及拒绝指标无真实生产链，同样属于阻断项。
实测容量低于 10 万规划假设时，如实记录容量与瓶颈；可按已验证的较低流量上限完成首次上线准备，稳定性门槛保持不变。
已冻结的延迟/错误预算未满足时，该负载点不能计入可靠容量；禁止事后改报告口径将它算作通过。
首次上线后发现问题，按预先验证的开关限制受影响写入/功能；仅在 schema 兼容且不破坏高水位时恢复已验证制品。
数据库恢复可能损失备份之后的数据，必须按冻结恢复目标处置并核对号段；它不是无损回退应用的替代方法。
全部矩阵有结果、阻断项关闭、剩余已知限制写明影响与运行处置、首次上线材料齐备，才算 M6 完成。
