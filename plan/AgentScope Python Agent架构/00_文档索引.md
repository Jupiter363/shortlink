## 2. 核心结论

最终架构不再保留 Java Agent Service。

Python Agent Service 负责认知编排、模型、会话、派生分析、多租户和沙箱；Java 现有业务系统负责身份、权限事实、业务命令、审批动作、风险策略生效以及 Gateway 热路径。

一句话原则：

> Python 负责认知与派生，Java 负责事实与兑现。

## 3. 使用方式

架构评审、需求设计、代码评审和上线评审必须回答以下问题：

1. 新能力属于概率性认知还是权威业务事实。
2. 是否破坏数据库、缓存和事件的单一所有者原则。
3. 是否允许模型或沙箱绕过 Java 权威命令边界。
4. 是否满足租户、身份、数据分类和最小权限要求。
5. 是否定义超时、重试、幂等、降级、可观测和回滚。
6. 是否通过对应阶段的验收门禁。

未回答上述问题的 Agent 功能不得进入生产实现。
