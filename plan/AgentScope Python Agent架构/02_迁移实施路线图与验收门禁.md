## 1. 迁移策略

迁移采用 Strangler Pattern，不进行一次性重写。

核心策略：

1. 先固定契约，再迁移实现。
2. 先迁移只读认知，再迁移派生计算。
3. 先建立 Java 权威边界，再允许 Python 创建提案。
4. 派生数据优先重算，不做高风险历史搬运。
5. 权威数据先保持单写者，再分离物理 schema。
6. Worker 切换必须单活，禁止双写策略。
7. 每阶段必须可独立回滚。

最终目标不是让新旧系统长期并存，而是在验证完成后删除 Java agent-service。

## 3. Phase 0：基线、契约与可回滚能力

### 3.1 目标

在改写任何生产实现前，把当前行为变成可验证基线。

### 3.2 任务

1. 冻结现有 Java Agent 对外 HTTP 请求和响应样例。
2. 导出现有数据库表、唯一约束、索引和状态枚举。
3. 冻结 Gateway 风险 Redis key、payload、TTL 和 Lua 行为。
4. 建立 Campaign Evaluation Dataset。
5. 建立 Security Risk Golden Dataset。
6. 为所有现有 Tool 建立输入/输出 JSON Schema。
7. 建立现有 API 黑盒 Contract Test。
8. 为 Agent 路由增加 Runtime Switch：

~~~text
JAVA_ONLY
PYTHON_SHADOW
PYTHON_CANARY
PYTHON_ONLY
~~~

9. 为风险 Worker 增加 runtime owner/fencing 配置。
10. 建立统一 traceId、clientRequestId 和 idempotencyKey。

### 3.3 数据集最低要求

Campaign Dataset 至少覆盖：

- 列出分组。
- 短链分页。
- 单链统计。
- 分组统计。
- 访问明细。
- 缺少 gid。
- 缺少日期。
- 多 Tool 请求。
- 越权 gid。
- Prompt Injection。
- 空数据和下游超时。

Risk Dataset 至少覆盖：

- 流量突增。
- IP 集中。
- 高重复访问。
- 小样本保护。
- 多规则叠加。
- 边界阈值。
- 无 LLM。
- 规则版本变化。
- 同一批次重试。
- 自动动作和人工动作分流。

### 3.4 Exit Gate G0

必须全部通过：

- HTTP Contract Test 可以对当前 Java 服务稳定运行。
- Redis 策略兼容测试包含 UPSERT、覆盖、过期和 compare-delete。
- Evaluation Dataset 有明确期望 Tool、事实字段和禁止行为。
- Runtime Switch 可在不发版情况下回退 Java。
- 所有真实 Secret 已从测试和文档清除。

未通过 G0，不得开始生产 Python 接入。

## 4. Phase 1：建立 Java Authority Facade

### 4.1 目标

先把 Java 的非 Agent 责任变成稳定、独立的权威契约，使 Python 不依赖旧 agent-service 内部结构。

### 4.2 目标模块

在 admin 中建立：

~~~text
authority.identity
authority.capability
authority.approval
authority.riskcontrol
authority.audit
~~~

### 4.3 迁移映射

| 现有 package | 目标 |
|---|---|
| harness/action | admin authority.approval |
| riskpolicy/action | admin authority.riskcontrol |
| riskpolicy/service | admin authority.riskcontrol |
| riskpolicy/outbox | admin authority.riskcontrol |
| riskpolicy/repository | admin authority.riskcontrol |
| riskcenter 的 review/policy command | admin authority.riskcontrol |
| business shortlink read tools | admin authority.capability |

不迁移到 Java Authority：

- Graph。
- LLM。
- Prompt。
- Agent Session。
- Risk Profile 派生计算。
- Risk Explanation。

### 4.4 迁移技巧

第一步可以让 admin Authority 继续连接现有 shortlink_agent schema，但必须做到：

1. 旧 agent-service 停止写对应 Authority 表。
2. admin 成为唯一写者。
3. Python 永远没有这些表的写权限。
4. 通过独立 DataSource 和数据库账号隔离。

稳定后再把 Authority 表迁入 shortlink_authority schema。不要同时进行代码归属、状态机重写和物理迁库。

### 4.5 API

建立稳定接口：

~~~text
/internal/short-link-admin/v1/agent-identity/token/exchange
/internal/short-link-admin/v1/agent-capabilities/*
/internal/short-link-admin/v1/approval-actions/*
/internal/short-link-admin/v1/risk-control/*
~~~

旧路径可以保留适配器，但新 Python 只依赖新契约。

### 4.6 Exit Gate G1

- admin 模块测试覆盖现有 PendingAction 全部状态。
- 重复 confirm 不重复执行。
- 非 replay-safe 失败不自动重放。
- 有效策略槽位和 Outbox 事务测试通过。
- Gateway Redis 兼容测试通过。
- agent-service 对 Authority 表已无生产写权限。
- Java Authority 不依赖 AgentRemoteService。

## 5. Phase 2：Python Runtime Foundation

### 5.1 目标

建立不含具体业务 Agent 的生产骨架。

### 5.2 工程骨架

创建 agent-runtime：

- Python 3.11+。
- AgentScope 固定版本。
- FastAPI。
- Pydantic v2。
- SQLAlchemy/Alembic。
- RedisStorage/RedisMessageBus。
- httpx。
- OpenTelemetry。
- uv.lock。

### 5.3 基础能力

实现：

1. Health、readiness、startup 检查。
2. Delegation JWT 验证和 JWKS 缓存。
3. mTLS Token Exchange 和短期 Authority Token 缓存。
4. Java Session Grant 与 Python Runtime Session 分离。
5. 首个合法 Run 懒创建 Runtime Session。
6. Session Revocation Event 和本地撤销缓存。
7. TenantContext。
8. Session、Run、Event 状态。
9. SSE 事件恢复。
10. Run budget 和 cancel。
11. AgentRuntimePort 与 AgentScope Adapter。
12. ModelGatewayPort。
13. Tool Registry 和 Schema。
14. 统一错误模型。
15. 数据脱敏。
16. Trace、Metrics、Audit。

### 5.4 AgentScope 约束

- 不把 AgentScope 自带 API 作为产品 API。
- 不直接暴露 credentials、workspace、model 管理路由。
- 不启用 Bash/Write 等默认高风险 Tool。
- AgentScope 版本只在 Adapter 层可见。
- 使用 RedisMessageBus，不使用 InMemoryMessageBus 生产多实例。

### 5.5 Exit Gate G2

- 多实例 Session/Run 锁测试通过。
- 同 session 不同用户访问被拒绝。
- Token 过期、错误 audience、错误 tenant 被拒绝。
- Runtime Token 无法直接调用 Authority API。
- Token Exchange 缺少 Python 服务身份时被拒绝。
- Authority Token scope 和过期时间不超过原 Runtime Token。
- Session Grant 撤销后活动 Run 被取消，后续 Runtime Token 被拒绝。
- SSE 断线恢复和事件去重通过。
- Run deadline、cancel 和预算耗尽通过。
- AgentScope 升级不影响产品 API Contract。
- Python API 在无模型配置时 fail-safe 启动或明确 readiness 失败。

## 6. Phase 3：Campaign Read-only Agent

### 6.1 目标

迁移收益最高、风险最低的 Campaign Analysis，只开放只读 Tool。

### 6.2 实现

1. 移植 System Prompt 和结构化响应。
2. 使用确定性 Slot Resolver 解析 gid、日期和短链。
3. 使用 AgentScope 受约束 Tool Loop。
4. Java Capability API 提供事实数据。
5. Python 完成排名、占比、趋势和卡片计算。
6. LLM 只解释 Tool 和确定性计算结果。
7. 保持现有同步 AgentRunResult 兼容适配器。

### 6.3 Shadow 策略

PYTHON_SHADOW 模式：

- 用户仍收到 Java 结果。
- 同一只读请求异步发送 Python。
- 对比 Tool 选择、事实字段、卡片和错误分类。
- Shadow 不创建 Proposal，不触发 Sandbox 外部写入。

### 6.4 质量门槛

建议初始门槛：

- 必需 Tool 选择准确率 >= 98%。
- 越权成功率 = 0。
- 事实字段一致率 = 100%。
- 结构化响应解析率 >= 99.5%。
- 无数据时编造指标次数 = 0。
- p95 平台额外开销满足主纲领 SLO。
- 平均 Token 成本在预算内。

### 6.5 Exit Gate G3

连续 7 天 Shadow 达标，且：

- 无 P0/P1 安全问题。
- Java/Python 数据来源一致。
- Python 降级行为清晰。
- Dashboard 和告警可用。
- Runbook 完成。

## 7. Phase 4：Direct Runtime Route 与 Sandbox

### 7.1 目标

消除 admin -> Python -> admin 同步环，并启用受控 Sandbox。

### 7.2 Session Bootstrap

新增：

~~~text
POST /api/short-link/admin/v1/agent/sessions
POST /api/short-link/admin/v1/agent/sessions/{id}/token/refresh
~~~

Gateway 新增 Python Runtime 路由。

浏览器使用 fetch streaming 或支持 Authorization Header 的 SSE 客户端，不在 URL 中携带 Token。

### 7.3 Sandbox 分阶段

1. 本地 Local Workspace，仅开发。
2. CI Docker Sandbox，验证文件和资源边界。
3. 生产 OpenSandbox/Kubernetes，deny-all 网络。
4. 先开放固定 Pandas 分析镜像。
5. 不允许在线 pip install。
6. 不开放内部网络。

### 7.4 Security Gate

必须验证：

- Sandbox 无法访问 metadata endpoint。
- 无法访问 admin/project/MySQL/Redis。
- 无法读取宿主文件和 Docker Socket。
- CPU/内存/PID/时间/磁盘配额有效。
- Workspace TTL 和强制回收有效。
- 恶意压缩包、路径穿越、软链接攻击被阻止。
- Sandbox 输出敏感扫描有效。

### 7.5 Exit Gate G4

- Direct Route 在 Canary 用户中稳定。
- admin Proxy 仅作为回退路径。
- Sandbox Security Suite 全通过。
- Sandbox 冷启动和成本符合预算。
- 关闭 Sandbox 时 Campaign Agent 可降级运行。

## 8. Phase 5：Risk Analysis Python Shadow

### 8.1 目标

迁移派生风险画像和确定性工作流，但不切换策略写入。

### 8.2 迁移范围

迁移到 Python：

- riskprofile model/detector/service。
- riskanalysis job/worker。
- SecurityRisk intake、feature、rules、scoring。
- LLM explanation。
- risk event/snapshot 的派生部分。

保留 Java：

- risk review。
- approval action。
- risk policy activation。
- effective policy。
- outbox/redis publisher。

### 8.3 数据策略

风险画像和评估属于可重算数据：

- Python 使用新表和新 schema。
- 不迁移历史中间状态。
- 根据相同事实快照重算。
- 必要历史仅迁移审计摘要。

### 8.4 Shadow 比对

同一 batch snapshot 同时输入 Java/Python 计算器，但：

- Java 仍是生产结果。
- Python 不创建真实 Proposal。
- 比较 score、level、reasonCode、evidence 和 autoEligible。
- LLM explanation 不要求文本逐字一致，只评估证据引用和禁止声明。

### 8.5 风险门槛

- 相同 rulesetVersion 确定性分数一致率 = 100%。
- reasonCode 集合一致率 = 100%。
- 自动动作资格一致率 = 100%。
- 同 batch/target 幂等 = 100%。
- 单目标失败不阻塞批次。
- 无 LLM 时批次可完成。

### 8.6 Exit Gate G5

至少两个完整业务周期 Shadow 达标，并完成：

- 租约丢失测试。
- Worker 崩溃恢复。
- 重复事件测试。
- 部分成功测试。
- 大批量容量测试。
- 无 LLM 降级演练。

## 9. Phase 6：Approval 与 RiskControl 切换

### 9.1 目标

Python 开始创建真实 Proposal，Java Authority 成为唯一执行和策略写入者。

### 9.2 切换顺序

1. 先开放 CREATE_SHORT_LINK Proposal。
2. 再开放 BATCH_CREATE_SHORT_LINK。
3. 再开放人工 Risk Proposal。
4. 最后开放 auto-eligible LIMIT_RATE Proposal。
5. DISABLE/BLOCK 等高风险动作始终人工确认。

### 9.3 Fencing

引入 authority_runtime_control：

~~~text
capability = RISK_ANALYSIS
owner = JAVA | PYTHON
generation = monotonic integer
lease_until
~~~

Java/Python Worker 领取任务时必须携带 generation。切换时增加 generation，旧 Worker 即使继续运行也不能提交结果。

禁止仅通过停 Pod 保证单活。

### 9.4 权威数据物理迁移

采用：

~~~text
expand -> backfill -> verify -> switch writer -> soak -> remove old access
~~~

校验：

- row count。
- 主键/唯一键。
- 状态分布。
- payload hash。
- policy effective slot。
- outbox 未完成记录。
- audit 链。

### 9.5 Exit Gate G6

- Python 无 Authority 表写权限。
- Java Authority 是唯一 Proposal/Policy 写者。
- 所有 Action 重复提交、确认和事件重放幂等。
- Gateway Redis 兼容测试通过。
- Fencing 可阻止旧 Worker 提交。
- 数据迁移校验无差异。
- 回滚演练完成。

## 10. Phase 7：全量流量与旧服务下线

### 10.1 Canary

建议顺序：

~~~text
内部用户
-> 1%
-> 5%
-> 20%
-> 50%
-> 100%
~~~

每一档至少观察：

- Error rate。
- p95/p99 latency。
- Tool failure。
- Token/cost。
- Sandbox failure。
- Approval duplicate。
- Policy outbox lag。
- Tenant authorization denial。

### 10.2 自动回滚触发器

建议触发：

- 5 分钟窗口 Agent 5xx > 2%。
- 越权或跨租户事件 > 0。
- 重复 Command > 0。
- Policy 错误覆盖 > 0。
- p99 Run accept 超过预算持续 15 分钟。
- Outbox lag 超过安全阈值。

安全或一致性事件必须立即回滚，不等待统计显著性。

### 10.3 下线条件

100% Python 流量稳定至少两个发布周期后：

1. 停止 Java Agent API。
2. 停止 Java Risk Analysis Worker。
3. 移除 service discovery 路由。
4. 删除 Spring AI Alibaba 依赖。
5. 归档旧 checkpoint 和派生表。
6. 保留 Authority 数据和审计。
7. 删除 agent-service Maven module。

### 10.4 Exit Gate G7

- 生产无 Java Agent 流量。
- 回滚窗口结束。
- 旧 Worker 和 Scheduler 不再运行。
- 依赖和配置扫描无遗留。
- 文档、Dashboard、告警、Runbook 指向 Python。
- Maven reactor 可在无 agent-service 下完整构建。

## 11. 回滚矩阵

| 阶段 | 回滚动作 | 数据处理 |
|---|---|---|
| Campaign Canary | 路由切 JAVA_ONLY | Python Run 保留审计 |
| Direct Route | Gateway 切 admin proxy | Session Token 失效 |
| Sandbox | 关闭 Sandbox Tool group | 会话继续无代码分析 |
| Risk Shadow | 停 Python Worker | 删除/保留派生数据均可 |
| Proposal Cutover | 禁用 Python Proposal scope | Java 已创建动作继续处理 |
| Risk Worker Cutover | generation 切回 Java | Python 旧 generation 提交被拒 |
| Policy Publisher | Java Outbox replay | Redis 从 Authority DB 重建 |

回滚不得删除已执行的权威业务事实。

时间不是放宽 Gate 的理由。任何阶段可以延后，但不得跳过安全和一致性门禁。

## 13. Definition of Done

每个阶段完成必须同时具备：

1. 代码。
2. 单元、合约、集成和必要 E2E 测试。
3. Schema Migration。
4. Dashboard 和告警。
5. Runbook。
6. 安全评审。
7. 容量数据。
8. 回滚开关和回滚演练。
9. 架构文档/ADR 更新。
10. Owner 明确。

缺少任一项只能称为开发完成，不得称为生产完成。
