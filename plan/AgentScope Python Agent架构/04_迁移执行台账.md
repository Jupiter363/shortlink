# AgentScope Python Agent 迁移执行台账

> 文档性质：非规范性实施记录

## 1. 当前结论

迁移已经开始，但尚未发生生产职责切换。

当前完成的是一个可回滚的只读 Campaign Agent 影子切片、三个跨 Java/Python 的版本化
capability 垂直切片、身份安全闭环，以及 Java 权威 Session Grant/JTI 撤销的同步闭环。
`list_groups`、`page_short_links` 与 `get_group_stats` 默认走 `/agent-capabilities/v1/groups/list`、
`/agent-capabilities/v1/short-links/query` 和 `/agent-capabilities/v1/group-stats/query`，其余两个
Tool 仍走迁移期 `/agent-tools/*`。
v1 路径可以使用 Delegation JWT、JWKS、mTLS Token Exchange 和 Authority Token；默认模式
仍为 legacy。Java `agent-service`、Maven 模块和生产路由均保持不变。

不得将本台账中的“已实现”解释为 G1、G2 或 G3 已通过。

### 2.2 Runtime 0.7.0

- FastAPI application factory、liveness、readiness。
- Java 兼容 health 与 chat 契约。
- 内部接口 fail-closed 鉴权和常量时间令牌比较。
- 请求 Body 禁止携带 username 等身份字段。
- 模型未配置时 readiness 与 chat 明确失败，不伪装可用。
- Framework-neutral `AgentRuntimePort`、模型和稳定错误类型。
- AgentScope `Agent`、`DeepSeekChatModel`、独立 Agent State adapter。
- AgentScope 仅注册五个显式只读 FunctionTool。
- 未注册 Bash、Write、Edit、任意 MCP 或任意 URL Tool。
- admin capability 路径 allowlist、超时、响应大小、日期和分页边界。
- Tool 数据进入模型前移除凭据字段并脱敏 IP/身份字段。
- AgentScope 运行错误不向 HTTP 响应反射 provider 异常细节。
- `get_group_stats` 默认调用版本化 POST capability，并支持
  `SHORTLINK_AGENT_GROUP_STATS_CONTRACT=legacy` 无数据回滚。
- `list_groups` 默认调用严格空对象请求的版本化 POST capability，并支持独立
  `SHORTLINK_AGENT_GROUPS_LIST_CONTRACT=legacy` 无数据回滚。
- `page_short_links` 默认调用版本化 POST capability，将旧 Tool 的 `orderTag` 映射为显式排序
  枚举，并支持独立 `SHORTLINK_AGENT_SHORT_LINKS_CONTRACT=legacy` 无数据回滚。
- Java `groups/list` 仅从已认证 `UserContext` 获取 owner，Authority Token 最小 scope 为
  `capability:group:read`；请求 Body 携带 username/owner 或任意未知字段时拒绝。
- Java 将分组数据收敛为 `gid/name/sortOrder/shortLinkCount`，限制 1000 行、唯一 gid 和非负
  短链数，生成 TTL 300 秒的 `admin/groups` Snapshot 与有序列表 canonical SHA-256。
- Python 对 v1 envelope、Snapshot、RFC 3339 时间、分组字段集合、数值边界、唯一 gid、响应
  大小和内容哈希逐层 fail closed，并保留 Snapshot provenance。
- Java `short-links/query` 在调用业务 Provider 前重新校验 gid 所有权，只发布短 URL、描述、
  有效期、创建时间与 today/total 的 PV/UV/UIP 指标，不发布数据库 ID、原始 URL、favicon、
  domain、shortUri、owner 或审计字段。
- Java 与 Python 共同校验分页回显和算术、页内唯一 URL、非负 32 位指标、`PERMANENT` 空到期
  时间及 `CUSTOM expiresAt > createdAt`；Snapshot 来源为 `admin/short-links`，TTL 为 300 秒。
- 短链分页 Authority Token 最小 scope 为 `capability:group:read`。Python 严格验证完整 `data`
  的 canonical SHA-256、请求回显与字段集合，v1 失败不得自动降级 legacy。
- 统计窗口统一为半开区间 `[start,end)`，Python 发送带时区 RFC 3339，Java 校验本地零点并
  映射到旧 Provider 的闭区间日期。
- Java 在调用下游前重新校验 gid 所有权，拒绝负数 Provider 指标，生成 TTL 300 秒的
  Snapshot 与 canonical SHA-256。
- Python 校验 `schemaVersion`、`requestId`、`gid`、Snapshot 来源和内容哈希，并向 Tool
  结果保留 Snapshot provenance 与 Provider warnings。
- v1 失败响应使用 capability 专用 Problem Details；成功响应不套旧 `Result` envelope。
- Java 使用固定版本 Nimbus JOSE/JWT，从只读挂载的私有 P-256 JWK 签发 ES256 Token；JWKS
  只发布公钥并支持轮换窗口旧 Key。
- Python 异步缓存 JWKS，限制 Key 数、响应大小、TTL 和未知 `kid` 刷新频率，严格校验
  `alg/typ/kid/iss/aud/iat/nbf/exp/ctx_ver/sid/scp/jti`。
- 兼容 chat 在 JWT 模式下只从 Claims 构造 Actor，忽略 trusted identity Header，并校验
  Token `sid` 与请求 Session 一致。
- Token Exchange 要求 TLS、已验证客户端证书、clientAuth EKU 和允许的 SHA-256 指纹；
  Authority Token 最长 120 秒、scope 不扩张且 exp 不超过父 Token。
- Python Authority Token 仅缓存在请求级 ContextVar，带并发 exchange lock；不进入 Actor、
  日志或全局缓存。
- Java capability 从 Authority Token 恢复 `UserContext` 与 `AgentAuthorityContext`，保留
  tenant/session/scope/act 供授权与审计，并继续校验 gid 所有权。
- Java/Python 都提供 legacy、dual 和强制 Token 模式；Bearer 校验失败时禁止降级。
- Java 提供服务端 `sid` Bootstrap、owner/tenant 绑定、Token Refresh 和幂等 Session Revoke；
  只允许创建 `campaign-analysis` Grant。
- `t_agent_session_grant` 以 `grant_version + latest_jti` 执行行锁和 CAS；Refresh 在同一事务
  撤销旧 JTI，Session Revoke 在同一事务更新 Grant、记录 JTI 并写权威 Outbox。
- Delegation 与 Authority Token 强制包含 `grant_ver`；Token Exchange 和 capability 热路径
  都重新核验 Grant owner、tenant、version、父 JTI、状态与到期时间。
- Java 提供 mTLS `/agent-identity/revocations/check`；Python 使用短 TTL 有界缓存、并发合并、
  inflight 硬上限和严格响应回显，Authority 不可达时 fail closed。
- `agent.session.revoked.v1` 已建立最小化 Schema、Outbox payload 和 Python 幂等摄取基础；
  事件不包含 owner、scope、JTI、Token 或业务原文。

3. 建立 Runtime Session/Run/Event 持久化、单 Session 活动 Run 约束与 SSE 恢复。
4. 完成真实 TLS 握手、Key/证书轮换、故障注入和回滚演练。

临时兼容不得扩展到写操作、审批确认、风险策略发布或 Gateway Redis。

## 5. 当前回滚方式

当前没有修改 admin 生产路由，也没有删除 Java 代码。回滚不需要反向迁移业务数据，但必须保留
已经产生的 Grant、JTI 撤销和 Outbox 权威事实：

1. 停止 Python Runtime。
2. 保持 admin 继续调用现有 Java `agent-service`。
3. 将 Session Grant 与 Token 模式按运行手册顺序关闭，不删除或降版 Java 权威事实。
4. 保留 Python 日志和测试结果用于差异分析。

当前切片没有 Python 权威数据，不需要数据反向同步；Java authority 的 expand-only 表不得在
认证回滚时删除。

分组统计 capability 如需紧急契约回滚，在 Python Runtime 设置
`SHORTLINK_AGENT_GROUP_STATS_CONTRACT=legacy` 并重启，仅恢复旧只读路径；不得删除 v1
接口或回滚 Java 业务数据。

分组列表 capability 使用独立 `SHORTLINK_AGENT_GROUPS_LIST_CONTRACT=legacy` 开关；该开关与
分组统计开关不得互相复用，也不得在 v1 校验失败时自动降级。回滚后仍由旧 Java internal API
执行业务 owner 隔离，不产生数据反向迁移。

短链分页 capability 使用第三个独立开关 `SHORTLINK_AGENT_SHORT_LINKS_CONTRACT=legacy`。该开关
只恢复旧只读 GET，不关闭或删除 v1 endpoint；v1 的 HTTP、Schema、分页或哈希失败均必须直接
失败，不允许自动请求 legacy。三个 capability 开关不能互相绑定。

身份回滚必须按 `AUTHORITY_TOKEN -> DUAL -> LEGACY` 顺序执行，先让 Java capability 接受
双协议，再让 Python 停止 Token Exchange，最后关闭 Java/Python JWT 入站模式。详细步骤见
`05_身份安全切片运行手册.md`。

## 7. 禁止事项

- 不得把当前兼容 `/chat` 直接配置为全部 Agent 的生产地址。
- 不得把 `security-risk` 路由到当前 Python Runtime。
- 不得为赶进度在 Python 增加 MySQL 业务表或风险 Redis 写权限。
- 不得以 AgentScope Permission 代替 Java 业务授权。
- 不得在真实模型 Key 缺失时将 readiness 强制改为成功。
